Five stops, one line

  1. queuepostsleuth queue

    Counts per queue, top domains, every delay reason grouped and classified into 17 causes with a hint.

  2. shapepostsleuth shape

    The qshape view: which destination is backing up, and since when, in age buckets.

  3. logpostsleuth log --since 24h

    Sent, deferred, bounced, expired, rejected per domain. Bounce causes. Domains still failing. Trace any message.

  4. dnspostsleuth dns

    MX, SPF (10-lookup limit, is your IP allowed), DKIM keys, DMARC, PTR with forward confirmation.

  5. doctorpostsleuth doctor

    All of it in one report with next steps. Exit code 1 when something is wrong.

Change here for your AI agent

postsleuth mcp is a Model Context Protocol server on stdio. Ask Claude, Cursor or any MCP client "why is mail to Gmail stuck?" and it calls the same tools you would run by hand. Run it on the mail host, through SSH, or next to a Postfix container.

  1. postfix_doctor
  2. postfix_queue_summary
  3. postfix_queue_list
  4. postfix_queue_shape
  5. postfix_log_stats
  6. postfix_log_trace
  7. mail_dns_check
  8. postfix_config
// on the mail server
{"mcpServers": {"postsleuth": {
  "command": "postsleuth", "args": ["mcp"]}}}
// from your laptop, over SSH
{"mcpServers": {"postsleuth": {
  "command": "ssh", "args": ["mx1", "postsleuth", "mcp"]}}}
// Postfix in Docker (docker-mailserver, mailcow)
{"mcpServers": {"postsleuth": {"command": "postsleuth",
  "args": ["mcp", "--wrap", "docker exec -i mailserver"]}}}

The siding is locked

Every tool reads. Flush, requeue, hold, release and delete live on a siding that stays locked unless you start postsleuth with --allow-mutations. Your agent cannot unlock it. Even when it is open, each change over MCP needs confirm=true, takes explicit queue IDs, and ALL is refused.
